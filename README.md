# 传奇放置 · LEGEND

> 以 CSV 定义驱动的本地放置 RPG：三职业、自动战斗、地图推进、BOSS 挑战与离线结算。

用 [Zan](https://github.com/joyspinch/zan-lang) 语言写的独立游戏项目（仓库根自带 git 仓库）。完整设计与实现说明见 [`PROJECT.md`](PROJECT.md)。

## 玩法

- 三职业、自动战斗、技能耗蓝与冷却、地图推进、BOSS 挑战、本地挑战曲线、离线结算。
- 地图玩法分离：野外驻守与幻境推层双轨道——传送保存幻境层数/波次，驻守地图循环刷怪不推层，随时返回幻境恢复推层进度；驻守状态与幻境轨道写入版本化存档。
- 装备掉落、穿戴、职业/等级/转生条件、背包与仓库、锁定、独立出售/回收、图鉴收集；整理不会换装，自动配装为独立操作。
- 装备独立生命/法力、攻击/魔法/道术/防御/魔防上下限；角色逐项聚合；匹配伤害类型的减伤。
- 表驱动的四种锻造、等级成长、修炼、任务、转生、商店和消耗规则。
- 八槽内功：TP/黑铁消耗、独立等级与属性、离线击杀 TP、旧存档兼容。具体数值为模板配置而非已知原版公式。
- 天书传承：十二槽天书实例可穿戴，选择背包材料将更高系数转移到已穿戴天书，失败不消耗；天书属性按表驱动。
- 符文之语（模板规则）：传说武器/男衣/女衣 = 赤血魔剑或城主战袍 + 传说矿石×2000 + 13#符文；形态增长 = 传说装备[第N形态] + 龙珠N★×100 + 新13#，保留系数/品阶/强化；合成与增长全部原子校验并写入存档。传说矿石、龙珠1★–9★与13#符文按模板定价在商城出售，基础装备出自巅峰塔深层掉落池；第九形态为模板终点，依赖传奇黄的最终传说与传说洗炼未收录。
- 36 张统一透明底装备族图，所有可穿戴定义通过 `data/equipment_art.csv` 显式映射，不再按槽位取截图。
- 藏宝图六格奖励池：专用库存、资源/装备奖励、满包原子失败、每日福利补图、今日抽取计数与版本化存档。
- 稳定定义 ID 的版本化 JSON 存档、损坏配置拒绝加载、存档加载后重新计算属性。

联机 PK、行会、沙巴克、交易、排行榜等没有服务器支持，不制造玩家或战报。原始 41 条技能、475 条配方、251 条称谓、52 条套装等保留在 `data/reference/`，不宣称已全部执行；当前运行时技能已接入三职业各八槽配置，原始技能库仍未逐条还原。天书传承已接入（更高系数转移、材料消耗、失败原子性与存档）；宝石成长已接入六槽独立等级、属性聚合、普通升级与 1→5 合成阶段；符文之语已接入模板化的传说锻造与形态增长（公开配方的本地化执行，13#/龙珠/矿石按模板定价供应，传奇黄系最终形态未收录）；普通升级和合成都按表驱动且资源不足时不扣除；内功已接入八槽模板规则。竞技场、押镖、爵位/称谓页已接入本地可验证闭环（NPC 对手、离线押镖结算、资源消耗与属性成长），但不冒充真实玩家或服务端。藏宝图已接入本地六格抽取循环，但服务器奖池刷新与会员/师徒来源未实现。祭坛已接入 page 14 的本地捐献、个人领取与共建奖励闭环，个人/共建进度支持溢出保留并写入版本化存档；全服排行、昨日补领与跨玩家共建仍需真实服务端。勋章、龙珠等额外槽位未实现；当前支持十二个穿戴位置，且纸娃娃已加入运行时装备图标叠层，但尚非原版身体部件透明分层。重量、基准售价、堆叠上限等已导入（出售已使用基准售价），但尚未实现负重系统、通用消耗品背包和原版商店经济；不能把这些元数据当成已完成玩法。

详见 `data/README.md` 的字段、映射依据与规则边界。引用素材来自本地参考资料；对外分发前需要自行确认素材和原始数据授权。

## 构建

需要 [zan-lang](https://github.com/joyspinch/zan-lang) 仓库（`zanc` 编译器、公共包与 stdlib 都在里面）：

```powershell
git clone https://github.com/joyspinch/zan-lang.git
$env:ZAN_HOME = 'D:/path/to/zan-lang'   # 指到刚克隆的 zan-lang 仓库根

pwsh -File client/tools/build.ps1
```

服务端另有一套工程（`server/`），用 `client/tools/build.ps1` 只构建客户端。

产物：`build/legend-game/Legend.exe`（运行目录要带上它旁边的 `assets/` 与 `skins/`）。

## 运行

```powershell
cd build/legend-game
.\Legend.exe
```

## 服务端凭据

`server/` 是独立的服务端工程，仓库里**不含任何可用凭据**：`config/app.json` 的
`[auth].secret`（会话 Cookie 签名密钥）与 `[auth].bootstrapPassword`（空库种子
口令）都是空串，服务端因此默认拒绝一切管理后台登录。首次本地起服用随仓库提供的
引导工具，它会随机生成这两个值、存进 gitignore 的本地文件，并注入进程环境：

```powershell
python server/tools/dev_env.py launch
```

口令模型、环境变量覆盖方式与公网部署要求，见
[`server/README.md`](server/README.md) 的「凭据模型」一节。
